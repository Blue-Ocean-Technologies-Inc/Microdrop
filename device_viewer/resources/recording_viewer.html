Recording Viewer

The Recording Viewer plays back the camera videos MicroDrop recorded during an experiment. It can show them the way the Device Viewer showed them at the time: lined up with the chip drawing, with the electrode outlines and the switched-on electrodes drawn on top. You can also mark the part of the picture you care about and save a new, cropped video.

This tutorial covers the Recording Viewer pane. Making a recording is covered in the Camera & Alignment Tutorial. There is no real footage of this pane yet: the pictures are schematics, and the interactive player below is a mock-up that follows the same rules as the real one.

Overview

Open it with View ▸ Recording Viewer. It is not part of the default layout, so it stays hidden until you tick it there.

  • What it plays. The .mp4 and .mkv files in one folder, by default the recordings folder of the current experiment.
  • What it adds. A device-aligned view rebuilt from the alignment saved beside each recording, and an optional device overlay: electrode outlines and the electrodes that were on at each moment.
  • What it saves. A rendition: a new video next to the recording, lined up and/or cropped to your regions. The original recording is never changed.
The pane is deliberately small: play, pause and a position slider. It has no speed control, frame stepping, looping, markers or keyboard shortcuts; see What it does not do.

Quick walkthrough

  1. 1Make a recording

    Click Start Recording Video in the camera controls, and click it again to stop. Or tick Record on protocol steps: a run of ticked steps becomes one video.

    Either way the file lands in the experiment's recordings folder, with the alignment and (when a device is loaded) the electrode timeline saved beside it (see Where files go). The Camera & Alignment Tutorial covers the camera, the recording settings and the alignment.

  2. 2Open the pane

    Click View ▸ Recording Viewer. The pane looks in the current experiment's recordings folder, picks the newest recording and shows its first frame, paused.

    If the folder is empty or does not exist yet, the Recording list is empty, the video area stays black and the play controls are greyed out.

  3. 3Pick a recording and play it

    Choose a file in the Recording list. Click to play; it turns into while playing. Drag the slider to jump to another moment. The read-out shows position / length in minutes and seconds.

    Scroll the mouse wheel over the video to zoom, and drag to move the picture.

  4. 4Line it up with the chip

    Click to switch to the device-aligned view: the picture is turned and straightened the way the Device Viewer showed it while recording.

    In that view, draws the electrode outlines and fills the electrodes that were on at the current moment. The number box after each sets its opacity in percent.

  5. 5Mark the region you care about

    Pause where the action starts. Switch on Edit Region and drag a box on the video. That box is a region keyframe at the current time. Move to a later moment and drag again to make the crop follow the droplet.

    clears all the regions. Switch Edit Region off to pan with the mouse again.

  6. 6Save the rendition

    Click . The text beside the toolbar reads Exporting…, then counts the seconds processed, then Saved name. You can keep working while it runs.

    The new file sits next to the recording. Click to see it in the Recording list.

Terms

The words the pane and its tooltips use.

Recording Recording list

One camera video file made by MicroDrop.

What it is

An .mp4 or .mkv file holding the camera's own, unaligned frames. MicroDrop writes two small files beside it: .transform.json (the alignment) and, when a device was loaded, .overlay.json (the electrode outlines and which electrodes were on, over time).

When to use it

Any time you want to look again at what happened on the chip.

How to read it

The list shows file names, oldest first. Free recordings are named free_mode_date-time; recordings from the protocol's Record column are named after the first recorded step: description_step id_date-time. The date-time is in UTC, such as 2026_11_11-16_20_02.

Typical value

The newest recording of the current experiment, shown paused on its first frame.

Recordings folder Choose folder, Back to experiment and Re-scan buttons

The one folder the list is read from.

What it is

By default, the recordings folder inside the current experiment folder. Only the files directly in it are listed (no sub-folders), and only .mp4 and .mkv files.

When to use it

Use to look at an older experiment's videos, and to come back. After you start a new experiment, click Home to follow it.

How to read it

The list updates by itself when a recording finishes: the pane jumps back to the current experiment's folder and selects the new file, even if you were browsing another folder. Files added in other ways appear after .

Typical value

experiment folder/recordings; see the Help, Logs & Saved Files Tutorial for where experiment folders live.

Device-aligned view Device-Aligned toggle

The recording shown as the Device Viewer showed it: straightened and placed under the chip drawing.

What it is

A recording keeps the camera's raw frames. The .transform.json beside it holds the camera alignment in use when the recording stopped. The viewer applies it to every frame, so the electrodes in the video sit where the drawing's electrodes are.

When to use it

To compare the video with the electrode layout, to use the device overlay, or to save a lined-up video.

How to read it

The button is greyed out when the recording has no .transform.json (for example a file copied in from elsewhere, or a saved rendition). The result is only as good as the alignment was: set it up first with the Camera & Alignment Tutorial. Switching the view refits the picture.

Typical value

Off: each recording opens in the raw view.

Device overlay: Device Outline and Actuations Device Outline and Actuations toggles, with their opacity boxes

The chip drawing, redrawn on top of the video.

What it is

Device Outline draws every electrode's outline. Actuations fills the electrodes that were switched on in the Device Viewer at the current playback time. Both come from the recording's .overlay.json, which MicroDrop writes while recording when a device is loaded.

When to use it

To check that a droplet was where the protocol switched electrodes on, or to make a saved video easier to follow.

How to read it

Only in the device-aligned view. Actuations show what the Device Viewer displayed as on, not a reading from the hardware. They change in steps, at the moments the display changed. The number boxes set each layer's opacity from 0 to 100 %. The toggles and opacities are remembered between sessions, and a saved device-aligned rendition includes the layers that are on.

Typical value

Both off; opacity 100 % each. At 100 % the Actuations fill hides what is under it: lower it to see the droplet through the fill (try it in the mock player).

Region keyframe Edit Region toggle; drag on the video

A box drawn at one moment of the recording, saying "crop to here from now on".

What it is

Each region is a rectangle plus the playback time at which you drew it. A region holds until the next one; before the first region, the first region applies. So one region means "crop the whole video here", and more regions at later times make the crop follow the action.

When to use it

When only part of the chip matters, or a droplet travels and you want the saved video to follow it.

How to read it

The dashed yellow box on the video is the region in use at the current time. The crop jumps from one region to the next; it does not glide between them. Drawing again at exactly the same time replaces that region. A tiny box (a stray click) is ignored. Regions belong to the view they were drawn in: draw in the other view (raw or device-aligned) and all existing regions are dropped, and the box is only shown while that view is on.

Typical value

None. Regions are saved in recording.roi.json and come back when you open the recording again; deletes them all (there is no way to delete just one).

Rendition Save button

A new video made from the recording: lined up, cropped, or both.

What it is

MicroDrop decodes the recording with FFmpeg, straightens each frame if the rendition is device-aligned, draws the overlay layers that are on, crops to the region of that moment, and encodes an H.264 .mkv file next to the recording. The original recording is untouched.

When to use it

To share or analyse just the part that matters, or to keep a lined-up copy that plays in any video player.

How to read it

With regions, the rendition is made in the view the regions were drawn in, whatever the pane shows. Without regions, it is the view on screen; Save stays greyed out in the raw view with no regions, since there would be nothing to change. A device-aligned rendition is named recording_aligned.mkv, a raw cropped one recording_cropped.mkv; saving again overwrites it. A video cannot change size, so every frame comes out at the size of the first region, and later regions of another shape are stretched to fit.

Typical value

Same length and average frame rate as the recording. Large recordings take a while; the status counts the seconds processed.

Fit vs saved zoom and centre Fit button; mouse wheel and drag on the video

How the video is framed in the pane.

What it is

Once you zoom or pan, MicroDrop remembers the zoom and the centre point and reuses them, also for the next recording and after a restart. Fit means the whole frame fills the pane.

When to use it

Click when the picture has drifted out of sight or is zoomed too far. The device-aligned picture can land partly outside the pane, so a saved framing is often what you want while you work on one chip.

How to read it

While no framing is saved, the picture refits whenever the pane is resized. Switching Device-Aligned on or off also clears the saved framing and refits.

Typical value

Fit (nothing saved).

Where files go

Everything lives side by side in the recordings folder. The name of each extra file is the recording's name with another ending.

FileWhat it isWritten by
name.mp4 or .mkvThe recording: raw camera framesThe recorder; the format follows Edit ▸ Preferences ▸ Video Settings ▸ Video Recording
name.transform.jsonThe camera alignment, for the device-aligned viewThe recorder, when the recording stops
name.overlay.jsonElectrode outlines and which electrodes were on, over timeThe recorder, when a device was loaded
name.roi.jsonYour region keyframesThe Recording Viewer, as you draw; removed by Clear
name_aligned.mkv / name_cropped.mkvA saved renditionThe Recording Viewer's Save

Keep the .json files with the video when you copy or move a recording: without .transform.json there is no device-aligned view, and without .overlay.json no overlay. A saved rendition is itself listed as a recording after a re-scan, without either file.

Pictures from Capture Image and the protocol's Capture column go to the captures folder and are not shown here.

What it does not do

  • No playback speed, frame-by-frame stepping, looping or keyboard shortcuts. Very small slider moves (under about a third of a second) are ignored.
  • No markers for protocol steps or phases on the timeline; the only thing drawn from the run is the device overlay.
  • No still-frame export, no clip trimming by time, no deleting or renaming files. Use the file browser for those.
  • No list of region keyframes and no deleting a single region; Clear removes them all.
  • No sound: MicroDrop records video only.

Caveats

  • The alignment is the one at the end. The .transform.json is written when the recording stops. If you re-aligned the camera during the recording, the whole video uses the last alignment.
  • A finished recording takes over the pane. When any recording ends, the viewer jumps to the current experiment's folder and selects the newest file.
  • Re-scan selects the newest file. After saving a rendition, Re-scan shows it and selects it; pick the original again from the list to keep working on it.
  • The first region sets the size. Draw later regions with roughly the same shape, or the saved video is stretched.
  • Saving needs FFmpeg. It runs in the background; long or high-resolution recordings take a while. Saving again overwrites the earlier rendition of the same kind.
  • Playback uses the computer's own video support. The viewer plays files through Qt Multimedia, so a file whose codec this computer cannot decode does not play here.

Glossary

Alignment
How the camera picture is turned and straightened to sit under the chip drawing; set in the Camera Alignment window.
Actuated electrode
An electrode switched on, so it pulls a droplet towards it.
Codec
The way a video is compressed, such as H.264.
Experiment folder
The folder where MicroDrop keeps one experiment's files: recordings, captures, logs.
FFmpeg
A video tool MicroDrop uses to save renditions.
Keyframe
A setting stored at one moment of a video, used from there on.
Region of interest (ROI)
The part of the picture you want to keep.
Rendition
A new video made from a recording, lined up and/or cropped.
Sidecar
A small file stored beside a video, with the same name and a different ending.
UTC
Coordinated Universal Time; file names use it so they sort the same everywhere.
