Device files, channels and connections

MicroDrop draws your chip from a device file: an SVG drawing with one shape per electrode. The file also says which DropBot channel drives each electrode and which electrodes are connected, so a droplet can move between them.

This tutorial is for anyone who loads their own chip design or fixes its wiring. It covers loading and saving device files, changing channel numbers, editing connections, and setting the electrode area so the capacitance and volume readouts are right. The three interactive figures run without a chip.

Overview

Most of what this page covers lives in two places: the File ▸ Device menu and the Device Viewer itself (the Numbers mode button, the right-click menu and the Calibration section of the side panel).

  • Electrodes come from the paths in the layer named Device. Each path's id is the electrode's name, for example electrode012.
  • Channels come from each path's data-channels attribute: the DropBot output wired to that electrode. Routes, the tooltip and droplet detection all work by channel.
  • Connections say which electrodes are neighbours. You can only drag a route, autoroute or step with the arrow keys between connected electrodes. If the file has none, MicroDrop works them out from the electrode shapes.
  • Area is worked out from each shape, in mm². The capacitance calibration and the live volume readout use it. A scale stored in the file corrects it when the drawing is not true to size.
  • Zones are kept in the file too. They have their own tutorial: Help ▸ Tutorials ▸ Zones Tutorial.
Neighbouring tutorials cover the rest of the Device Viewer: switching electrodes, routes, the tooltip and the view settings (Device Viewer Tutorial), rotating the device and lining up a camera (Camera & Alignment Tutorial), and zones (Zones Tutorial). All are in Help ▸ Tutorials.

Quick walkthrough

From a new chip design to a device file you can trust. Steps 2 to 5 are only needed when something in the file is wrong or missing.

  1. 1Load the device file

    Choose File ▸ Device ▸ Load… and pick the .svg file. A file from outside your Devices folder is copied into it first, and the copy is what MicroDrop opens and saves.

    The chip appears in the Device Viewer, and the pane's title shows the file name. Next time MicroDrop starts, it opens this device again.

  2. 2Check and fix the channel numbers

    Rest the pointer on an electrode: the tooltip shows its Channel. To change it, press N (or click Edit Electrode Channels under Paths), click the electrode, type the number and press Enter. Press N again to go back to the mode you were in.

    See Channels for the rules.

  3. 3Check the connections

    Choose File ▸ Device ▸ Edit Connections. A window shows the chip with a dot on every electrode centre and a white line for every connection.

    Drag from one dot to another to add a connection. Click a line (it turns orange) and press Delete to remove it. Every change shows in the Device Viewer at once; close the window when you are done. See Connections.

  4. 4Make the electrode area true to size

    The tooltip's Area (mm²) should match the real electrode. If it does not, right-click an electrode and choose Adjust Electrode Area Scale. Type the electrode's real area in Measured Area (mm²) and click Set Scale. Every electrode on the chip is scaled by the same factor. See Area and calibration.

  5. 5Calibrate the capacitance

    With a DropBot connected, switch on electrodes that are fully covered by liquid and click Measure Liquid Capacitance in the side panel's Calibration section. Then switch on electrodes covered only by filler (air or oil) and click Measure filler Capacitance. The Cl and Cf values appear next to the buttons, and the live Volume readout starts working.

  6. 6Save the device file

    Channel, connection and area changes add (modified) to the pane's title. Choose File ▸ Device ▸ Save to write them into the file; the tag goes away.

    Save As… writes a copy under a new name, but MicroDrop keeps the original file open: load the copy if you want to go on working on it. Zone edits are not tracked by the tag, so save after drawing zones too.

Inside a device file

You can draw a device file in any program that saves SVG (Inkscape is common). MicroDrop needs only a few things from it; this part lists them.

Device SVG

The drawing of one chip design: an outline per electrode, plus optional connections, zones and scale.

A plain SVG file. MicroDrop looks for a top-level group (an Inkscape layer) with an attribute whose whole value is Device, in any capitals; Inkscape keeps it in the layer's label. Each <path> directly inside it that has both an id and a d outline becomes one electrode. Anything else in that layer, such as nested groups or rectangles, is skipped.

<g inkscape:label="Device" inkscape:groupmode="layer">
  <path id="electrode000" data-channels="0" d="M 10,10 H 12 V 12 H 10 Z"/>
  …
</g>

Every time you bring a new chip design into MicroDrop.

If the file has no Device layer, or no usable paths in it, the load fails with Error: Cannot Load Device SVG.

MicroDrop ships with 90_pin_array.svg, 84 electrodes on channels between 0 and 119.

Electrode and electrode id

One shape on the chip. Its id is its permanent name.

The id, such as electrode079, is what protocols store for each step and what the tooltip shows on its first line (Electrode ID). MicroDrop never renames electrodes.

When you compare a protocol with a device, or write a device file by hand.

Keep the ids when you edit a design: a protocol made on the old file finds its electrodes again only by id (see Protocols and devices).

electrode000, electrode001, … in the bundled files.

Channel (data-channels)

The DropBot output wired to the electrode, as a whole number.

Switching an electrode on switches its channel on, so every electrode with the same channel goes on and off together. Droplet detection also works per channel.

Set once per chip design, to match how the chip's contact pads reach the DropBot's pins.

One number per electrode. An electrode without the attribute has no channel: its label is blank and its tooltip says Channel: None.

0 to 119 on a 120-channel DropBot (see Number of channels).

Curved outlines

Round and curved electrodes are turned into many-sided shapes.

Straight pieces of an outline (move, line, horizontal, vertical, close) keep their corner points. Each curved piece (an arc or a Bézier curve) is replaced by 24 points along the curve. An Inkscape circle, drawn as two arcs, becomes a 48-sided shape that is within about 0.2 % of the true circle.

Chips with round reservoirs or rounded electrodes.

Areas, centres and generated connections all come from this many-sided shape. An outline that crosses itself is repaired: MicroDrop keeps its largest piece.

Drawing units

MicroDrop turns every coordinate into millimetres, using the unit of the drawing's width and height.

If width and height both end in mm, cm, pt (1/72 inch), pc (12 pt) or px, coordinates are read in that unit. With no unit, they count as px, at 96 px per inch (1 px = 0.2646 mm). The viewBox is not used, and only a plain translate(x, y) on the Device layer is applied; transforms on single paths are ignored.

When the tooltip's areas look wrong for a new design.

When a drawing's units do not match its coordinates, every area is off by the same factor. Fix it once with the area scale, or save the drawing with its transforms flattened and its width in the units of its coordinates.

The bundled files have no unit, so they are read as px.

Centroid

The centre of an electrode's shape: where connection lines start and end.

The balance point of the outline. For an odd shape, such as an L-shaped reservoir, it can lie outside the electrode.

Edit Connections draws a dot on every centroid; you drag between dots to connect electrodes.

The channel number is placed separately, at the roomiest point inside the shape, so it is not always on the centroid.

Connections layer

A layer of straight lines, one per pair of connected electrodes.

A top-level group with an attribute whose whole value is Connections (any capitals). Each <line> counts from its start to its end, and each <path> from its first point to its last. A line connects the two electrodes its ends land on.

MicroDrop writes this layer on Save whenever the connections were generated or edited, replacing the old one.

Lines that miss an electrode are tried again with the electrodes grown a little, up to ten times. A line that crosses more than two electrodes connects the first and last. If any line still touches fewer than two electrodes, the whole layer is ignored and MicroDrop generates the connections instead; the device then opens marked (modified).

90_pin_array.svg has 125 connections.

Zones layer

Where the device's zone regions are kept.

One entry per region, listing its zone type and its electrode ids. MicroDrop rewrites this layer every time the device is saved. The Zones tutorial explains regions.

A region that names electrodes the file does not have is trimmed or dropped on load, with a Zones Not Loaded warning; saving then writes it without them.

Stored scale

The area scale, kept in the file's <metadata> as <scale>0.92</scale>.

Read on load; written on Save into the existing <metadata> element.

A file without a <metadata> element does not keep the scale: Save writes everything else and drops the scale without a warning. Inkscape files normally have one; check by reopening the device.

1.0 (no correction) when the file has none.

Loading and saving

All in File ▸ Device, next to the protocol menu. MicroDrop keeps device files in one folder and opens the last one you loaded.

Devices folder

The folder MicroDrop keeps device files in.

Devices inside MicroDrop's data folder in your Documents (Documents/Sci-Bots/Microdrop/Devices). Whenever they are missing, MicroDrop puts two files there: 90_pin_array.svg and pin_map.svg (one electrode for each channel, 0 to 119, and no connections).

Save As opens here; Load opens at the current device's file. A device loaded from anywhere else is copied in first.

There is no setting for this folder in the Preferences window; it is always this one.

Load…

Open a device file and show it in the Device Viewer.

If the current device has unsaved changes, you are asked first (Unsaved Device SVG Changes). A file already in the Devices folder is opened as it is. A file from elsewhere is copied into the Devices folder under the same name and the copy is opened. If a file of that name is already there, you see Warning: File Already Exists:

Loading clears the switched-on electrodes and the routes, closes the Edit Connections and Camera Alignment windows, and empties the Undo list. The loaded file becomes the Default Device Layout.

Save and Save As

Write the device back to a file.

Save writes into the file you loaded: every electrode's channel (an electrode with no channel loses its data-channels), the scale, the Connections layer if the connections were generated or edited, and the Zones layer. The rest of the drawing is kept.

Save As… opens in the Devices folder and writes the same things into a new file, adding .svg if you leave it off.

After Save As, MicroDrop still has the original file open: the title keeps its name, a later Save writes to it, and next start opens it. To carry on in the copy, load the copy.

After changing channels, connections, the area scale or zones.

(modified) and Unsaved Device SVG Changes

How MicroDrop tells you the device has changes that are not in the file.

A channel change, a new area scale, and generated or edited connections add (modified) to the Device Viewer's title. Loading another device while it shows asks Current device svg has unsaved changes. Proceed without saving?: Yes loads and drops the changes, No stops.

Zone edits do not set the tag. Closing MicroDrop does not ask either: save before you quit.

No tag after a load, unless the file had no usable connections and MicroDrop generated them.

Default Device Layout and the bundled 90_pin_array.svg

The device MicroDrop opens when it starts.

Every successful load sets it, so MicroDrop reopens the last device you loaded. You can also pick a file in the Preferences window; it is used the next time MicroDrop starts.

If the setting is empty, or the file it names has been moved or deleted, MicroDrop falls back to 90_pin_array.svg in the Devices folder. Before it does, it replaces that file with the original that ships with MicroDrop whenever the two differ. Edits saved into 90_pin_array.svg are then lost, so keep your own versions under another name (Save As, then load the copy).

Devices/90_pin_array.svg on a new installation.

Channels

Each electrode has at most one channel. Several electrodes may share a channel, and an electrode may have none. The figure lets you try all three.

Edit Electrode Channels (Numbers mode)

The mode for typing channel numbers onto electrodes.

or N. The label above the buttons reads Mode: Channel Edit. Click an electrode: its number is selected, so what you type replaces it.

  • Only digits can be typed or pasted.
  • Enter, or a click somewhere else, keeps the new number. Esc keeps the old one.
  • Delete all the digits and press Enter to take the channel away.
  • A number from 0 to Number of channels − 1 is accepted; a bigger one is ignored and the old number comes back.

When the file's channels do not match how the chip is wired, or a new design has none yet.

The change shows at once, marks the device (modified) and reaches the protocol tree. Undo does not undo it: type the old number back. Press N again to return to the mode you were in.

Number of channels

How many channels your DropBot has; it sets the highest channel number you can type.

Valid channels are 0 to this value − 1.

It limits typing only. A device file with higher numbers still loads.

120.

Several electrodes on one channel

Allowed, and MicroDrop does not warn about it.

The electrodes are wired together, so they always switch on and off together. Clicking one switches on all of them; a route through one actuates all of them; droplet detection cannot tell them apart.

On purpose, for large reservoirs split into several shapes, or for chips with fewer pads than electrodes. By mistake, after a typo in Numbers mode.

Their areas add up: the area MicroDrop uses for that channel is the sum of all its electrodes.

One electrode on several channels

Not supported.

data-channels must hold one whole number. A list such as "3,4" (a form some older device files use) stops the whole file loading with Error: Cannot Load Device SVG. Split such an electrode into one shape per channel, or keep one of the numbers.

Electrodes with no channel

Drawn, but not wired to anything.

A click does not switch it on, it cannot be disabled, and droplet detection and zone checks never see it. A route can still pass over it, but it is never actuated.

Decorations, alignment marks, or electrodes you have not numbered yet.

Number every electrode before you build a protocol. While any electrode has no channel, the protocol tree does not take up the device's channel list (an error goes to the log) and keeps the one it had before, so protocol steps may not switch the electrodes you expect.

Channel numbers on the chip

The numbers drawn on the electrodes are a layer you can fade or hide.

The Electrode text row of Alpha Settings sets their opacity; its eye hides them. The Connections row does the same for the connection lines. The Device Viewer Tutorial explains Alpha Settings.

The numbers turn with the chip when you rotate the device view, so they stay upright. Rotation is a view setting kept in MicroDrop's preferences, not in the device file.

Both shown at 100.

Disable Electrode

Take a damaged electrode out of use. It works on the channel, not the shape.

Disabling one electrode disables its channel, so every electrode sharing that channel turns red and stops responding together. The item appears only on electrodes that have a channel; Enable Electrode brings it back.

When the DropBot reports channels it has disabled itself, the Device Viewer shows that list instead. The Advanced Mode preference Allow hardware disables (on to start with) controls this. Disabled channels are not saved in the device file.

Connections

A connection says "a droplet can move straight from this electrode to that one". MicroDrop uses the connections, not the shapes, whenever it needs to know which electrodes are next to each other.

  • Drawing a route (Draw and Edit modes): dragging onto an electrode adds it to the route only if it is connected to the last one.
  • Autoroute finds the shortest chain of connections between two electrodes. No chain, no route.
  • Arrow-key stepping moves to the connected electrode in that direction.
  • Wide routes (the Lanes settings) use them to find the electrodes beside a route, and zones use them to tell which electrodes of a region touch.

Generate Connections

Work out the connections from the electrode shapes, replacing all the ones there are.

MicroDrop grows every outline by a small margin (the average electrode area ÷ 100, read as millimetres), fills in any dents, and connects each pair whose grown outlines touch, except pairs that sit diagonally: when the line between their centres is between 30° and 70° away from straight up-and-down, they are left out.

For a new design without a Connections layer (MicroDrop also does this by itself on load), or to start over after editing.

Generating replaces hand edits too, and the Device Viewer's Undo cannot bring them back. Always look the result over in Edit Connections: electrodes drawn with a wider gap get no connection, a big reservoir may connect only to the electrode straight across from its centre, and on a staggered (brick) layout the 30°–70° rule keeps the slanted pairs between rows but drops them between columns, so a layout staggered by columns comes out as separate columns.

Marks the device (modified); Save writes a new Connections layer.

Edit Connections

A window for adding and deleting connections by hand.

The window shows the chip alone, with a dot on every centroid and a white line for each connection. Its title row reads Connections — and the device's name; hover it for the instructions.

Routes over removed connections

Existing routes stay as they are.

Deleting a connection does not change routes or protocol steps that already use it; MicroDrop only notes it in the log. New routes cannot be drawn across it.

Redraw such routes if the connection was removed because the droplet cannot actually make that move.

Area and calibration

The volume readout turns a capacitance reading into microlitres using electrode areas and two calibration values. If the areas are wrong, the volume is wrong by the same factor, even after calibrating.

Electrode area

The size of an electrode in mm², worked out from its shape and multiplied by the area scale.

The tooltip shows it with two decimals. The Electrode Area Scaler shows both the Original Area from the drawing and the Scaled Area. The area of a channel is the sum of its electrodes.

Check it once for each new design against the chip's real dimensions.

MicroDrop adds up the areas of the switched-on channels for each calibration and volume reading.

About 4.3 mm² for the small square electrodes of 90_pin_array.svg (scale 1.0).

Area scale (Electrode Area Scaler)

One number that multiplies every electrode's area, to make the drawing true to size.

Right-click an electrode, choose Adjust Electrode Area Scale, enter that electrode's real area in Measured Area (mm²). Scaling Factor shows Measured Area ÷ Original Area; Set Scale applies it to the whole chip, Cancel does nothing.

When the drawing's units are off (see Drawing units) or the chip was made at a different size than drawn.

The factor always starts from the original areas, so setting it again replaces the old one; it does not stack. It marks the device (modified) and is saved in the file's metadata. Measure Cl and Cf again after changing it.

1.0. The Measured Area box always starts at 1.0, not at the current area: type the real area before you click Set Scale.

Cl (liquid capacitance)

The capacitance of liquid-covered electrode per mm².

The DropBot's latest capacitance reading divided by the area of the switched-on electrodes.

Once per chip and liquid: switch on electrodes completely covered by the liquid you will use, wait for a steady reading, then measure.

Shown with two significant figures, in nF/mm², pF/mm² or fF/mm² (1 nF = 1000 pF = 1,000,000 fF), whichever keeps the number readable; - until measured. Nothing happens if no electrode is switched on or there is no reading yet (no DropBot connected).

No fixed value: it depends on the chip's coating and the liquid. It must be higher than Cf.

Cf (filler capacitance)

The capacitance of electrode covered only by filler (air or oil) per mm².

Measured like Cl, with switched-on electrodes that have no liquid on them.

After Cl, on the same chip.

Without it, the volume readout takes Cf as 0. If Cf is not lower than Cl, the readout shows Liquid calibration must exceed the filler calibration.

Lower than Cl.

Reset Measurements

Clears Cl and Cf back to -.

Cl and Cf are kept in MicroDrop's preferences, so they survive a restart and are shared by every device. Reset and measure again when you change chip, coating or liquid.

Plate gap and the volume readout

The volume is the liquid-covered area times the gap between the plates.

Covered area = (reading − Cf × switched-on area) ÷ (Cl − Cf); volume = covered area × gap. The gap is the Plate gap (µm) preference.

Until Cl is measured the readout says Measure the liquid capacitance to calibrate. With nothing switched on it says No actuated electrodes. A covered area larger than the switched-on area means liquid outside them, or a stale calibration.

Plate gap 254 µm.

Protocols and devices

A protocol remembers electrodes by id, not by position, and keeps a copy of the channel each id had.

What a protocol stores about the device

Each step's electrodes and routes as electrode ids, plus the device's electrode-to-channel list.

The list is kept up to date from the loaded device: when you load a device or change a channel, the open protocol takes the new list, and the next protocol save writes it. Runs use it to turn a step's electrodes into channels. The device file itself is not stored in the protocol.

Load the right device before you open or run a protocol.

Opening a protocol made on another device

MicroDrop compares the protocol with the device on screen and warns you.

A Protocol warnings dialog lists what does not match, with details:

  • N electrode(s) referenced by this protocol do not exist on the current device, with the steps that use them;
  • N electrode(s) map to a different channel on the current device than the protocol expects, for example electrode012: protocol ch 12 -> device ch 40.

Proceed anyway opens it, Cancel does not.

If you proceed, the protocol takes the current device's channels: a step still names the same electrode ids, and switches whatever channels those ids have now. Electrodes the device does not have are not switched.

When a chip design was renumbered, or a protocol is shared between labs with different devices.

Caveats

  • Save As keeps the original open. Load the copy to work on it; a later Save writes to the original.
  • Do not keep your edits in 90_pin_array.svg. When the Default Device Layout is empty or names a missing file, MicroDrop overwrites that file with the bundled original.
  • Zone edits are not tracked by (modified), and nothing asks you to save when MicroDrop closes.
  • The scale needs a <metadata> element in the file, or it is lost on Save without a warning.
  • Number every electrode before building a protocol; an electrode with no channel stops the protocol tree from picking up channel changes.
  • One channel per electrode. A comma list in data-channels stops the file loading.
  • Review generated connections. Wide gaps, big reservoirs and staggered layouts can leave out connections you need, and generating again throws away hand edits.
  • Calibrate after changing the area scale or the chip. Cl and Cf are shared by all devices, and MicroDrop divides them by the new scale whenever the scale changes, also when you load a device whose file stores a scale. That is only right when the scale was 1.0 before.
  • Calibration needs a connected DropBot and liquid or filler on the switched-on electrodes.

An electrode's permanent name in the file, such as electrode012.
