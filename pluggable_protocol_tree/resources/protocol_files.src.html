Protocol Files & Experiments

MicroDrop keeps two kinds of things for you. A protocol file is your recipe: the steps, saved as one .json file wherever you choose. An experiment folder is your lab notebook: one folder per session, where every run leaves its data, its report, a copy of the protocol it ran, pictures and notes.

This page shows how to save and open protocols, what AutoSave and Undo do, what a run leaves behind, and how to bring in protocols from the old MicroDrop. Where each folder sits on your computer is in Help ▸ Tutorials ▸ Help, Logs & Saved Files; this page links there rather than repeating it.

Overview

The protocol file and the experiment folder are separate. Saving a protocol never touches the experiment folder, and a new experiment never changes the protocol you have open.

Protocol file

  • What the protocol is: steps, groups and every column value.
  • You save it (Ctrl+S); AutoSave then keeps it up to date.
  • Lives where you saved it. The dialogs start in Documents\Sci-Bots\Microdrop\Protocols\<device name>.
  • One file, many runs. Share it by copying it.

Experiment folder

  • What happened: logs, run data, run reports, protocol copies, pictures, videos, notes.
  • MicroDrop writes it for you. A new one starts each time MicroDrop starts, and when you click New Experiment.
  • Lives in Documents\Sci-Bots\Microdrop\Experiments\<date and time>.
  • Many runs, one folder, until you start a new experiment.

Paths are written Windows style. On macOS, Linux and the Raspberry Pi they use /, and Documents is in your home folder there too.

Quick walkthrough

From a fresh experiment to a saved protocol, a run and its report. It assumes a chip is loaded in the Device Viewer and you have a protocol with a few steps (the Protocol Tree tutorial shows how to build one).

  1. 1Start an experiment for this piece of work

    Click New Experiment on the Experiment: line above the protocol tree, or choose File ▸ Experiments ▸ New Experiment. The name after Experiment: changes to the new folder's name: the date and time, in UTC.

    Click that name: the folder opens in your file browser. It already holds logs; everything else appears as you work.

  2. 2Save the protocol once

    Press Ctrl+S with the protocol pane in focus, or click Save Protocol under the tree. The first time, a Save Protocol window asks for a file name. It opens in the Protocols folder of the loaded device. Type a name and click Save.

    The pane's title changes from untitled to your file name. From now on, AutoSave writes your changes to that file.

  3. 3Edit; AutoSave keeps the file current

    Change a cell, say a Duration. The title shows [modified]. About 1.5 seconds after your last change, AutoSave writes the file and [modified] goes away. The green glyph in the status bar, and the AutoSave box under the timeline, show that AutoSave is on.

    Changed your mind? Ctrl+Z (protocol pane in focus) or takes the edit back; AutoSave then writes that too.

  4. 4Run it and answer the questions at the end

    Press Play. When the run finishes, MicroDrop asks Create New Experiment?. Yes starts a new experiment folder for the next run; No keeps the current one. Either way the report of this run goes into the folder the run started in.

    Then Generating Run Report... shows for a few seconds, and Run Summary Generated links to the report. Click the link to open it in your web browser. A run you stopped asks Generate Run Summary? instead (End-of-run questions).

  5. 5Look at what the run left

    Choose File ▸ Experiments ▸ Open Experiment Folder. You find the run's data (data), its report (reports), a copy of the protocol exactly as it ran (protocols) and the log (logs). Steps that took pictures or videos filled captures and recordings.

    If you answered Yes to Create New Experiment?, the open folder is the new one: go up one level to Experiments and open the previous folder. What a run leaves behind lets you try each ending.

  6. 6Open a report again later

    Press R with the protocol pane in focus, or click Browse session reports. The Session Reports window lists the reports made since MicroDrop started, newest first; double-click one to open it.

    Reports from earlier sessions are not listed there: open their experiment folder's reports.

  7. 7Bring in a protocol from the old MicroDrop

    Choose File ▸ Protocol ▸ Import Legacy…. Point MicroDrop folder: at the old MicroDrop's folder, pick the Device and the Protocol, and click Import.

    MicroDrop converts the steps, saves them as a new protocol file and shows Legacy protocol imported. Open its details to see what could not be converted (Old MicroDrop protocols).

Protocol files

Opening, saving and sharing the protocol you build in the protocol tree.

Protocol file

One file holding one protocol: every step, group and column value.

A text file in JSON format with the ending .json. The dialogs list it as Protocol JSON (*.json). Its file name is the protocol's name: MicroDrop shows it in the pane's title.

Save a protocol you want to run again, change later or give to someone. Open it with Ctrl+O or File ▸ Protocol ▸ Load….

You never need to read it, but you can: What is inside a protocol file takes one apart. Do not edit it by hand; a broken file will not open (Load error).

A few kilobytes for a short protocol. Nothing is saved until you save it the first time: a new protocol is untitled.

Protocols folder

Where the Save, Load and Import windows open.

One folder per device: Protocols\<device file name>, for example Protocols\90_pin_array, or Protocols\Null when no device is loaded. MicroDrop creates it when a window opens.

Keep each protocol beside the device it was written for: a protocol only makes sense on its own chip design (Opening on another device).

It is only a starting point: you can save anywhere. There is no setting for it in Edit ▸ Preferences; the Help, Logs & Saved Files tutorial shows where Documents\Sci-Bots\Microdrop is on each computer.

Documents\Sci-Bots\Microdrop\Protocols\90_pin_array.

New, Open, Save and Save As

Every way to start, open and save a protocol.

Use Save As… before you start changing a protocol you want to keep unchanged: AutoSave would otherwise write your changes into it.

Create New, Load… and Import Legacy… first check for unsaved changes (Unsaved changes). The buttons and their keys work while the protocol pane has focus and are greyed during a run.

The [modified] marker

Tells you the protocol on screen differs from its file.

The pane's title reads Pluggable Protocol Tree - <name>, with [modified] on the end while there are unsaved changes. <name> is the file name without .json, or untitled.

It compares the steps with the last save, not the number of edits: change a value and change it back, and the mark goes away. With AutoSave on and a file, it shows only for the moment before AutoSave writes. If it stays, AutoSave is off, the protocol has no file yet, or a save failed.

No mark right after a save, a load or New.

Opening on another device

What a protocol remembers about the chip, and what MicroDrop checks when you open it.

A protocol stores electrodes by their id in the device file (such as electrode001), plus the channel each electrode had when it was saved (electrode map). It does not store which device file it was written for, and opening it does not load a device.

With a device loaded, Load… compares the two and may show Protocol warnings:

  • … electrode(s) referenced by this protocol do not exist on the current device, with the step IDs that use them;
  • … electrode(s) map to a different channel on the current device than the protocol expects.

Proceed anyway opens it; Cancel keeps what you had. Expand the details for the list.

Load the right device (Device Viewer) first, then the protocol. If you proceed on another device, the wrong electrodes may switch on.

No warning on the device the protocol was written for. Once a device is loaded, the protocol takes that device's electrode map, so the next save stores the new map and the channel warning does not come back for that file.

Opening without a column's plugin

Columns such as Voltage, Magnet or a heater setpoint come from plugins. A protocol that uses one needs that plugin loaded.

When a column in the file has no plugin loaded, Load… shows Protocol has errors: … column(s) in this protocol have no matching plugin; their values will be dropped on load. The details list the column ids.

Click Cancel, load the plugin (Tools ▸ Manage Plugins…) and open the protocol again. Click OK only if you mean to lose those values.

After OK the protocol opens without those columns. The file is not changed at once, but the next save writes it without them, and with AutoSave on that happens after your next edit. To keep the original, use Save As… before editing. The same goes for a plugin unloaded while MicroDrop runs: its values come back if you load it again in the same session, but a save made while it is gone writes the file without them.

Import a protocol into a group

Copies the steps of another saved protocol into the group you selected.

Select exactly one group, then click Import protocol into selected group (Ctrl+Shift+I) and pick a file. Its top-level steps are added at the end of the group, with their values. The button is greyed unless one group is selected.

Only the top level comes in: a group in that file arrives as an empty group, without its steps. Values of columns that are not loaded here are skipped without a warning, and nothing is checked against the device. One Ctrl+Z takes the whole import back.

Reusing a block, such as a wash sequence, in a bigger protocol. To bring in a whole protocol with its groups, open it instead and copy and paste the rows.

AutoSave and Undo

AutoSave writes your edits to the protocol's file; Undo takes edits back. They work together: an undo is an edit too, so AutoSave writes it.

AutoSave

Writes the protocol back to its own file shortly after you stop editing.

About 1.5 seconds after your last change, the protocol is saved to the file it was last saved to or opened from. It never picks a file for you: a protocol that has never been saved is not written. During a run it writes nothing; changes made during the run are written once, when it ends. Before New, Load, Import Legacy and closing MicroDrop, waiting changes are written at once.

Leave it on. Turn it off to try edits you might not keep, then Save As… if you want them. Turning it on again saves edits still waiting.

in the status bar is green while AutoSave is on and grey while it is off; clicking it, or the AutoSave box beside Phase navigation, switches it. Hover over either for what it is doing:

  • AutoSave on – save the protocol once to start: no file yet.
  • AutoSave on – changes are saved to <file> automatically: working.
  • AutoSave on – paused while the protocol runs; pending changes are saved when it ends.
  • AutoSave on – the last save failed: … It retries on the next change.
  • AutoSave is off. Turn it on to write protocol changes to the protocol file automatically.

If a write fails (a full disk, a read-only or unplugged drive), an AutoSave Failed warning appears once. Your changes stay in MicroDrop and [modified] stays; the next change tries again, or use Save As… to pick another place.

On. The choice is remembered across restarts. Opening a protocol never rewrites its file.

Undo and Redo

Take back protocol edits, one action at a time, and put them back.

Ctrl+Z undoes the last edit; Ctrl+Y or Ctrl+Shift+Z redoes it. The keys work while the protocol pane has focus; the Device Viewer has its own Ctrl+Z. One entry per action: a Bulk Set over twenty steps, a paste of five rows, or electrodes clicked into a step each undo in one go.

The tooltip names the edit: Undo Edit Duration (s) (Ctrl+Z), Undo Delete Step, Redo Move Rows. Nothing to undo and a greyed button mean the history is empty. A new edit clears what is left to redo.

Any slip in the tree. Undo works after a save too: the protocol is then [modified] again and AutoSave writes the undone state.

The last 100 edits. The history is cleared by New, Load, Import Legacy and when a plugin adds or removes a column; Save does not clear it. Nothing is undone or recorded during a run. While you are typing in a cell, Ctrl+Z undoes the typing instead.

Experiments

Where your runs leave their results. The Help, Logs & Saved Files tutorial has the full folder map and a Where is my …? lookup; this part is about how experiments and runs fit together.

Experiment folder

One folder that collects everything a session wrote.

Named after the moment it began, in UTC, as YYYY_MM_DD-HH_MM_SS. MicroDrop starts one every time it starts, and another each time you click New Experiment or answer Yes to Create New Experiment?.

Start a new experiment for each new sample, chip or day, so each folder holds one story. Runs of the same protocol on the same sample can share one.

Several runs in one folder are told apart by time: each run's data and report files carry its local time in their names (YYYYMMDD_HHMMSS), the folder name is UTC.

Many folders hold only logs: MicroDrop was started and nothing was run. Prune Experiments clears them away. A folder that is completely empty when MicroDrop closes is deleted, but that rarely happens because the log is written there from the start.

Experiments folder

The folder that holds all your experiment folders.

Experiments inside Documents\Sci-Bots\Microdrop, next to Devices and Protocols. MicroDrop creates it at the first start.

Back it up; it is your data. Copy single experiment folders to share a result.

No menu item opens it directly: open the current experiment folder and go up one level. There is no setting for it in Edit ▸ Preferences.

C:\Users\<you>\Documents\Sci-Bots\Microdrop\Experiments.

Active experiment

The experiment folder MicroDrop is writing into right now.

Its name is shown after Experiment:, underlined. Click it, or choose File ▸ Experiments ▸ Open Experiment Folder, to open the folder. Right-click it to switch its tooltip off (Enable Tooltip).

The log, pictures and videos go to the active experiment as they happen; a note goes to the experiment that was active when you opened it. A run's data and report go to the experiment that was active when the run started, even if you start a new one at its end.

Check it before you press Play: that is where the run's results will be.

A fresh folder, named by the time MicroDrop started.

What a run leaves behind

Pick how a run ended. New files are marked; click any entry to see what writes it and when.

logs

MicroDrop's diary while this experiment was active.

One text file per experiment, microdrop.frontend.<computer>-<process>.log, started when the experiment starts. It covers everything MicroDrop did, not only the runs.

Attach it when you report a problem.

One line per event, with time and level; search for ERROR. The Help, Logs & Saved Files tutorial explains it in detail.

Always present.

data

The measurements of each run, in two files with the same content.

data_<run start>.csv (opens in a spreadsheet) and data_<run start>.json. One row per DropBot capacitance reading during the run, plus rows other plugins add (PMT, fluorescence …).

For your own analysis or plots. The report is built from the same rows.

Click a column name in this example:

Written at the end of every run that is not a Preview, a few seconds after it ends (the Logs Accepted Post-Protocol wait, 3 s). A run stopped before its first step writes empty files.

reports (the run summary)

One web page per run: what ran, with summary tables and charts.

report_<time>.html. It lists the run's settings (experiment, device file, dielectric, steps run, start and stop time, a link to the protocol copy), links to the data files, a summary of each measured column, one chart per column by step, a map of how long each electrode was on, and the run's pictures and videos.

To review or share a run. The Run Summary Generated window links straight to it.

Open it in a web browser. Its charts load a chart library from the internet, so they stay blank offline; the tables do not need it. The time in its name is when the report was written, a little after the data files' time.

Written after a finished run, and after a stopped run if you answer Yes to Generate Run Summary?. One report covers all repetitions of Repeat Protocol.

Auto-saved protocol copy

The protocol exactly as it ran, kept with its results.

protocols\protocol_<UTC time>.json, a full protocol file. It is written at the end of every run that is not a Preview, whether the run finished or not, and has nothing to do with your own file or with AutoSave.

To know what produced a result, even after you changed the protocol. Open it with Load… to run it again, then Save As… to give it a proper name and place.

The report's Protocol Path links to it. The step_id in the data files is the step's id in this copy.

One file per run.

captures

Camera pictures.

PNG files from the Device Viewer camera: from a step's Capture column, or taken by hand. Some cameras add a 16bit_raw folder, and the Portable DropBot's PMT a pmt folder.

Open them in the image viewer for analysis.

Pictures taken during a run are also shown in its report.

Only present if a picture was taken.

recordings

Camera videos.

Video files from the Device Viewer camera: from a step's Video / Record columns, or recorded by hand.

Videos recorded during a run are listed in its report with a play placeholder.

Only present if a video was recorded.

Notes

Sticky notes you write during an experiment, kept in its folder.

New Note opens a small window titled Exp: <experiment name>. Type, format with the buttons at the bottom, and save with or Ctrl+S. Each note is a file Notes\1.html, 2.html … that opens in a web browser.

The label at the top reads Unsaved, Saved (1) or Unsaved changes (1). Saving again overwrites the same file. changes the note's colour and saves it.

Anything worth remembering: the sample, a lot number, what you saw.

Nothing is saved until you save: closing the window does not ask. Clicking New Note again while a note of the same experiment is open brings that note to the front.

Session reports

The reports made since MicroDrop started, in one list.

Browse session reports (R) opens Session Reports: Name, Size, Date Created, newest first. Type in Search: to filter by file name; double-click or Open opens the report in your web browser.

It does not look on disk: reports from earlier sessions are not in the list, even in the same experiment. Hover over a name for the full path.

Empty right after MicroDrop starts. Greyed during a run.

Prune Experiments

Clears away experiment folders in which nothing happened.

Finds every experiment folder that holds only logs (and empty folders), never the active one, and asks Delete … experiment folder(s) that hold only logs?, with the names in the details. Yes moves them to the Recycle Bin (Trash on macOS and Linux), where you can restore them.

No experiments to prune means every folder holds data. If the computer's MicroDrop is missing the package that moves files to the Recycle Bin, it offers to update the environment first.

Now and then, to keep Experiments readable.

Old MicroDrop protocols

File ▸ Protocol ▸ Import Legacy… converts a protocol saved by the old MicroDrop (version 2) into this one's format. It asks about unsaved changes first.

MicroDrop folder (root directory)

Where to look for old devices and protocols.

Any of three: the old MicroDrop's own folder (it has a devices folder), a single device folder, or a folder holding device folders. Type it and press Enter, or use Browse.... The Device list fills from it.

Documents\MicroDrop if that folder exists, otherwise empty. The window remembers your last choices.

Device folder

One old device: its drawing and its protocols.

A folder with a device.svg and a protocols folder. The Device list shows each by its folder name; the Protocol list shows the old protocols in its protocols folder (files without an ending, other files are skipped).

The folder name becomes the device's name here: the imported device file and the protocol's folder are named after it.

Device SVG and Protocol file

The two files actually used, filled in from the lists.

The paths of the device drawing and the protocol. You can type other paths here, for files kept outside a device folder; what is typed wins over the lists.

The device SVG supplies the electrode-to-channel map. Import error means a field is empty, a file could not be read, or the SVG has no electrodes with channels.

Always use the device the protocol was written with: electrodes are matched by id.

What happens on Import

  1. The device file is copied into Documents\Sci-Bots\Microdrop\Devices as <device name>.svg. If a different file of that name is there, Device Name Conflict asks: Save Copy saves it as <device name> (2).svg, Don't Save leaves the device folder alone.
  2. If the Device Viewer shows another device, or none, Device mismatch offers to load this one: Yes loads it, No keeps the current one, whose wiring may not match.
  3. The steps are converted. MicroDrop may show Protocol has errors or Protocol warnings as on any open.
  4. The result is saved as Protocols\<device name>\<old protocol name>.json, never over an existing file (a second import gets (2)), and becomes the open protocol. Undo is cleared.
  5. Legacy protocol imported says how many steps came in; its details hold the conversion report.

Caveats

  • AutoSave writes into the file you opened. To keep a protocol unchanged, Save As… a copy before you edit, or switch AutoSave off.
  • A new protocol is not saved until you save it. AutoSave starts only after the first save, and nothing warns you while you build an untitled protocol, until you open another one or close MicroDrop.
  • A protocol does not remember its device file. Load the right device first; MicroDrop only warns when electrode ids or channels do not match.
  • Opening without a column's plugin drops its values after OK, and the next save (yours or AutoSave's) writes the file without them.
  • The File ▸ Protocol menu is not greyed during a run, unlike the buttons under the tree. Do not open, create or import a protocol until the run has ended.
  • New Experiment is not greyed during a run either. The run's data and report still go to the folder it started in, but its protocol copy, and pictures taken after the switch, go to the new one. Start new experiments between runs.
  • Session reports lists this session only. Older reports are in each experiment's reports folder.
  • Report charts need the internet. Offline, the report's tables show but its charts stay blank.
  • Notes are not saved by closing. Press Ctrl+S in the note first.
  • Import into a group brings only the top level. Groups in the imported file arrive empty.
  • Experiment folder names are in UTC; data and report file names are in local time.

Glossary

Protocol file
A .json file holding one protocol's steps, groups and column values.
JSON
A plain-text format for structured data; MicroDrop's protocol and data files use it.
Experiment
A folder collecting one session's logs, run data, reports, protocol copies, pictures and notes.
Active experiment
The experiment folder MicroDrop is writing into now.
Run
One press of Play until the protocol ends or is stopped, Repeat Protocol included.
Run report
The web page summarising one run; also called the run summary.
AutoSave
Saving the open protocol to its file automatically, shortly after each change.
Electrode map
Which DropBot channel each electrode of the device is wired to.
Legacy protocol
A protocol saved by the old MicroDrop (version 2).
Device SVG
The drawing of a chip's electrodes, with each electrode's id and channel.
UTC
Coordinated Universal Time: the world reference clock, without your time zone.
